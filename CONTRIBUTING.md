# Contributing

Thanks for your interest. This is a **personal, source-available project**, and its
[LICENSE](LICENSE) does not permit derivative works — so the contribution model is deliberately narrow.

## Issues: welcome

Please open a GitHub issue for:

- **Bugs** — a plugin misbehaves, a hook errors, a skill doesn't fire when it should.
- **Documentation problems** — something is wrong, unclear, or missing.
- **Feature ideas** — tell us the outcome you want; we'll decide whether it fits.

There is **no SLA and no guaranteed response time** — this is a personal project maintained on a
best-effort basis. Clear, reproducible reports get the fastest attention.

## Pull requests: not accepted

Because the license forbids modified versions and derivative works, **PRs are not merged**. Please
don't open one — describe the change in an issue instead, and if it's a good fit it will be
implemented here. This keeps the codebase single-sourced under the license.

## Security

Do not file security problems as public issues. See [SECURITY.md](SECURITY.md) for the private
disclosure path.

## The knowledge-base content

The Gherkin/BDD reference content lives in the separate
[bdd-knowledge-base](https://github.com/markddavidoff/bdd-knowledge-base) repository and has its own
`CONTRIBUTING.md` and license (CC BY-ND 4.0). Content issues belong there.
